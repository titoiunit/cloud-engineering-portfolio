# AWS to Azure Service Map

This document maps familiar AWS services to their Azure equivalents.

The goal is to help me transfer my existing AWS knowledge into Microsoft Azure and understand cloud concepts across different providers.

## Core service mapping

| AWS | Azure | Concept |
|---|---|---|
| EC2 | Azure Virtual Machines | Virtual servers / compute |
| S3 | Azure Blob Storage / Storage Account | Object storage |
| Lambda | Azure Functions | Serverless functions |
| DynamoDB | Azure Cosmos DB | NoSQL database |
| RDS | Azure SQL Database | Managed relational database |
| ECS / Fargate | Azure Container Apps | Containerized application hosting |
| CloudWatch | Azure Monitor | Logs, metrics, monitoring |
| IAM | Microsoft Entra ID / RBAC | Identity and access management |
| VPC | Virtual Network | Cloud networking |
| Security Groups | Network Security Groups | Network access rules |
| Route 53 | Azure DNS | DNS management |
| CloudFront | Azure Front Door / CDN | Content delivery |

## Why this matters

Cloud platforms use different service names, but many of the core architecture patterns are similar.

Understanding this mapping helps me think in cloud concepts instead of only memorizing one provider.

## My learning focus

I already have hands-on AWS practice with Terraform, infrastructure, serverless, containers, and architecture projects.

Now I am using that AWS foundation to learn Azure more efficiently through hands-on projects.

## Key takeaway

The goal is not just to learn AWS or Azure separately.

The goal is to understand cloud architecture patterns that can transfer across providers.
